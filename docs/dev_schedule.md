# 開発スケジュール(衝動代替アプリ)

> 企画・仕様の詳細は別ファイル `app_concept.md` を参照。本ファイルは開発の進行計画に特化する。
> 発表会まで: 約1ヶ月弱(基準として約26日と想定)。

---

## 前提・時間の見積もり

- 作業ペース: 1日あたり1時間、多くて2時間。
- 単純計算: 1時間ペースで約26時間 / 2時間ペースで約52時間。
- 現実的な実働見積もり: 毎日は続かない(仕事・体調で休む日もある)前提で、**実働30〜40時間程度**。
- 判定: Rails経験者(学習歴7ヶ月)がDevise認証・CRUD・簡単なグラフ規模のアプリを作るなら、**MVPは届く範囲**。ただし余裕はなく、**バッファが薄い**。1つ大きくハマると苦しくなるため、「溶けやすい場所を避ける」設計で守る。

## 時間を溶かしやすい要注意ポイント(先に認識しておく)

1. **衝動ボタンの呼吸アニメーション**(Stimulus+カスタムCSS): 凝りだすと無限に時間が溶ける。→ **最後に回す**。
2. **Turbo Frames**(学びながらのため最初のハマりが重い): → **中盤(第3週)に置く**。
3. **環境構築**(Rails新規・PostgreSQL・Devise・Tailwind導入): 初手で溶けやすい。→ **第1週に最優先で片付ける**。

### 最重要の考え方
**「動かないカッコいいもの」より「動く地味なもの」の方が、発表では圧倒的に強い。**
先に"地味だが確実に動くアプリ"を完成させ、アニメーションは最後の「盛り」として作る。こうすれば、最悪アニメーションが簡易版(円が膨らむだけ)でもアプリとして成立し、発表できる。

---

## 4週間の逆算スケジュール

各週の終わりに「動く状態」が積み上がっていくことを重視する。

### 第1週:土台づくり(絶対に急ぐ)
- [ ] Rails新規作成、PostgreSQL接続
- [ ] Devise導入(登録・ログイン・ログアウト)
- [ ] Tailwind導入
- [ ] ログイン済みユーザーがトップ画面を見られる状態まで
- **週末のゴール**: 「認証済みユーザーがログインしてトップ画面を見られる」。環境構築は溶けやすいので最優先で終わらせ、精神的な余裕を作る。

### 第2週:データの背骨をつくる(CRUD)
- [ ] テーブル設計(users / urges=記録 / alternative_actions=代替行動)
- [ ] 代替行動の登録・削除(マザーデータ+自由入力のハイブリッド)
- [ ] 衝動が来たことの記録(まずは**アニメーションなし**で、ボタンを押したらDBに1件記録されるだけ)
- **週末のゴール**: アプリの「データが貯まる」中核が、地味だが確実に動く形で完成。

### 第3週:見せ場と動きをつくる
- [ ] 記録一覧+棒グラフ(Chart.js。主軸は「その日に衝動が来た回数」)
- [ ] ストリーク表示(衝動ボタンを開けた連続日数。今続いている分のみ)
- [ ] 「見てしまった」の任意記録の別入口
- [ ] 代替行動まわりを Turbo Frames で"アプリっぽく"する(部分更新)
- **週末のゴール**: 機能が全部そろっている状態。**第3週末で一旦"完成"とみなせる**のが理想。

### 第4週:磨きとバッファ(命綱)
- [ ] 衝動ボタンの呼吸アニメーション(Stimulus+カスタムCSS)を作り込む
      - 3-3-6呼吸(吸う3秒/止める3秒/吐く6秒)×3セット=36秒
      - 吸う=赤い円が広がる+連打で黄色い円が広がる演出 / 止める=ポヨンと揺れる / 吐く=鼓動型テンポで縮む+手応えフェードアウト
- [ ] デプロイ(本番で動くURL。デプロイ先は Render / Fly.io / Heroku 等から選ぶ)
- [ ] デモ用ダミーデータ投入
- [ ] スマホでの見た目調整(レスポンシブ確認)
- [ ] 発表リハーサル
- **週末のゴール**: 発表可能な状態。この週は「余った時間で良くする」週。遅れたらアニメーションを簡易版にしてリカバリーできる余地を残す。

---

## リカバリー方針(遅れた時の削りどころ)

優先度の低い順に削る。上から順に諦める候補:

1. 呼吸アニメーションの作り込み → 簡易版(円が膨らむだけ)に落とす
2. Turbo Frames での部分更新 → 通常のページ遷移でも機能はする(見た目の"アプリっぽさ"だけ妥協)
3. ストリーク表示 → 最悪、棒グラフがあれば自己理解の機能は成立する
4. 「見てしまった」の任意記録 → 余裕がなければ発展扱いに回す

※ 認証・代替行動CRUD・衝動記録・棒グラフの4つは**中核なので死守**する。
