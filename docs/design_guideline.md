### なぜ寒色系に変えたか(2026/08/11)

- **洗練されてすっきりした見た目のほうが、見ていてストレスがない。**
- **オレンジが主役だとしつこく感じた。**画面を開くたびに主張してくる色は、
  「刺激を足さない」という全体思想と実際には噛み合わなかった。

温かさより「澄んだ静けさ」を選んだ、という位置づけになる。
**責めない・急かさない・刺激を足さないというトーンの原則は変えていない**(下記)。色の温度だけが変わった。

### なぜ絵文字を使わないか(変更なし)

- 絵文字は視覚的にちらつき、わずかだが刺激になる。
- 「見てしまった/うまくいかなかった」場面で軽薄に見えるリスクがある。
  **"責めないトーン"と"軽く扱うトーン"は別物**であり、絵文字なしの方がその線引きを守れる。
- アイコンは使ってよい(Material Symbols の細い線のもの)。ただし主張しすぎない範囲で。

## デザイントークン

実装は `app/assets/stylesheets/application.tailwind.css` の `@theme` に集約する(Tailwind v4。`tailwind.config.js` は作らない)。

### カラー

| 用途 | 値 | 備考 |
|---|---|---|
| 背景 | `#f6faff` | **全画面共通。グラデーションは使わない** |
| カード面 | `#ffffff` | |
| 主アクション | `#2b6085` | 「落ち着いた」「衝動がきた」「ログイン」など |
| 副アクション | `#cee2f5` | 「代わりのことをする」、および**衝動ボタンの円** |
| 本文 | `#131d24` | 真っ黒を避ける |
| サブ・補足 | `#41474e` | |
| 枠線 | `#c1c7cf` | 影の代わりに 1px の細い線で面を区切る |

- **赤は使わない。**モック初期案では衝動ボタンの円が赤(`#b71422`)だったが、
  画面内で最も強い要素が警告色になるため、副アクションと同じ薄いブルーに変更した。
- 影は濃い黒を使わず、主色を薄く広げる(`0 8px 32px -8px rgb(43 96 133 / 0.15)` 程度)。

#### 赤の例外(2026/08/12 決定)

**禁じているのは「ユーザーの行動を責める赤」であって、赤そのものではない。**
保存に失敗した等、システム側の不具合を伝える flash には赤(`#ffdad6` / `#93000a`)を使ってよい。
これはユーザーの落ち度ではなく、伝わらないほうが困る情報だから。

一方、「見てしまった」の記録・ストリークが途切れた表示・衝動の記録そのものには、
警告色を一切使わない。ここが原則2(責めない)の守備範囲。

flash の成功側(`notice`)は緑ではなく主色の系統(`#ebf5ff` / `#2b6085`)にする。
成功を強調して煽るのではなく、淡々と伝えるため。

#### 背景を1段下げる(2026/08/13 決定・適用は Day 5)

`#f6faff` は白に近すぎて、寒色系の印象が弱かった。背景を1段下げる。

| 対象 | 変更前 | 変更後 |
|---|---|---|
| `--color-surface`(背景) | `#f6faff` | **`#e5eff9`** |
| 衝動ボタンの円 | `primary-soft`(`#cee2f5`) | **`#47799f`**(下記「円は逆に濃くする」) |
| `--color-notice`(flash) | `#ebf5ff` | 変更しない |

`#e5eff9` は Aetheric Calm の生成パレットの `surface-container`。
現背景と円の色のほぼ中間にあり、**値の出自がパレット内にある**(勝手に決めた中間色ではない)。

面の明度は、背景より明るい側に3段。上に乗っている面ほど明るい、で説明がつく。

| 面 | 色 |
|---|---|
| 背景 | `#e5eff9` |
| flash(notice) | `#ebf5ff` |
| 連打後のメモ欄(`--color-raised`) | `#f6faff` |
| カード | `#ffffff` |

#### 衝動ボタンの円は逆に濃くする(2026/08/13 決定)

当初は円も明るい側(`#f6faff`)に置いたが、白が強すぎた。
**明るい側は窓が狭い。** 背景 `#e5eff9` と白の間しか無く、実測で円 `#f6faff` は背景比 1.11:1、
白カードが 1.164:1。**円が白カードとほぼ同じ分離量になり、「連打して押す対象」に見えない。**

そこで明暗を反転させ、`primary-container`(`#47799f`)にした。背景比 4.01:1。
`primary`(`#2b6085`・5.79:1)も候補だったが圧が強すぎるので、1段やわらげたこちらを採る。
**彩度は `primary` より低いので「画面最大の要素の彩度を上げる」ことにはならず**、
寒色系へ転換した理由(オレンジがしつこかった)とは衝突しない。どちらもパレット内の値。

濃い面の下では `--shadow-soft` は見えないため、濃度を上げた `--shadow-lift` を別に持たせている。
影は残す。浮いているほうが「押せるもの」に見えるため。

**同時に直すもの**

- 連打後の入力画面のメモ欄 `bg-primary-soft/20`。背景が濃くなると「へこんだ面」ではなく
  「明るい面」に反転するので、白か `#f6faff` に寄せる
- 枠線 `outline/40` は、白カードと背景の明度差が出るぶん弱めてよい(消してもカードは成立する)
- 棒グラフの「0の日の線」(`outline/70`)は白カードの上なので影響しないが、実機で見え方を確認する

### 形・レイアウト

- 角丸は大きめ。カード 1rem / ボタン 1.5rem(またはピル形状)。チップ・バッジはピル
- 面は「白 + 細い枠線 + 淡いぼかし」で浮かせる。重いドロップシャドウは使わない
- 余白は 8px 基準。ゆったり取る(モバイルの左右余白 24px)

### 書体

- `Inter` を基本にする。ただし **Inter は日本語の字形を持たない**ため、日本語は
  フォールバック(`Hiragino Sans` / `Noto Sans JP` など)で表示される。実質、日本語部分は角ゴシック
- 旧方針の「丸ゴシック系」は破棄する

## トーンの原則(全画面共通・変更なし)

色が変わってもここは変えない。

1. **急かさない**: 衝動時に判断を増やさない。任意入力(トリガー・メモ)は小さく、スキップが自然に見えるように(連打後画面の縦比 1:2:7)。
2. **責めない**: 「見てしまった」記録や、ストリークが途切れた時も、色・文言で追い詰めない。「記録しました」「また今日から」と淡々と・優しく。
3. **刺激を足さない**: 派手なアニメーション・強い効果音・数値での報酬・煽る演出をしない。落ち着かせることがゴール。
4. **静かに励ます**: ストリークや棒グラフは、達成を煽るのではなく、そっと自己肯定につながる程度に。

## 画面ごとの決定事項(モック確定時 2026/08/11)

- **フッターナビは「ホーム / 記録 / 代替行動」の3つ。**「設定」画面は作らないので置かない
- **衝動ボタンの画面にはフッターを置かない。**36秒の最中に他画面への導線を出さない(原則1)
- **衝動ボタンに残り秒数を表示しない。**進行はフェーズの文言(吸って / 止めて / 吐いて)と円の大きさで伝える。
  連打回数・スコアを出さないのと同じ理由で、数字を見る画面にしない
- **提案画面の説明文は time_span 単位。**行動ごとの説明は持たない
  (`alternative_actions` に説明カラムを増やさないため)。アイコンも time_span から決まるものを使う
- **ログイン画面にパスワードリセット導線を置かない。**Devise の recoverable を入れていないため

## 記録ページの決定事項(2026/08/13 実装時に確定)

モック `_1` は棒グラフをトップに置いていたが、**グラフは記録ページ(`urges#index`)へ移し、
トップはストリークのみ**にした。トップの情報量を増やさないため。

### 棒グラフ

- **棒の上に回数の数字を出さない。**「なんとなく自分の波が見える」までで足りる。
  数字が並ぶと「多い/少ない」の評価が生まれる
- そのため**棒の高さはその期間の最大値が基準**になる。週をまたいで「先週より多い」は読めない。
  比較のための画面ではないと割り切った判断
- **記録が0件の日は、棒を消さず細い線(3px)を残す。**棒ごと消すと「その日が存在しない」ように見える
- **今日の棒だけ淡い色(`primary-soft`)、ラベルは「今日」。**「今日はまだ途中」の意味
- **期間は直近7日のみ。**1ヶ月表示はバッファ日(`dev_schedule.md`)

### 記録一覧

- **1件1行**(時刻 / 結果のチップ / メモか代替行動名)。カード型にすると1件90〜110pxになり、
  週20件で2000pxを超えるため
- **記録が0件の日は一覧に出さない。**0はグラフが見せているので、一覧に「記録なし」を並べると
  宿題を突きつけることになる
- 代替行動を選んだ記録は、メモではなく**選んだ行動名**を出す

### resolved のチップ

**青系 = ユーザーが選んだ結果 / グレー = 未入力**で線を引く。

| resolved | 見た目 |
|---|---|
| `calmed` | 青の枠線 |
| `took_action` | `primary-soft` の塗り |
| `pending` | グレーの枠線 |

- グレーが残るのは `pending` だけ。これは価値判断ではなく「まだ入力されていない」という事実
- 視覚的な重みは **代わりのことをした > 落ち着いた**。
  落ち着いたが最もよく出る記録なので軽くする

### gave_in の印(2026/08/14 決定)

**チップの列には混ぜない。**`resolved` とは軸が違うので、同じ列に並べると
「どちらか一方の状態」に見える。行の右端に主色の**小さな丸**(`h-2 w-2 rounded-full bg-primary`)を1つ出す。

- **絵にしない。**矢印(逸れて外へ行く)と目のアイコンを試したが、
  矢印は 20px で潰れ、斜めの矢印は「別タブで開く」に読める(行自体がリンクなので致命的)。
  目は「見る」しか表せず、依存対象の3本柱のうちタバコがこぼれる
- **丸は壊れず、価値判断も持たない。**「何かある」としか言わないので責める方向に転びようがない。
  何の印なのかは詳細画面(`urges#show`)が言葉で言う
- 印が無い行も同じ幅の枠を確保する。有る行だけ列が伸び縮みすると、時刻とチップの位置が行ごとにずれる
- **赤もグレーも使わない。**赤は本ファイル「赤の例外」の禁止範囲そのもの。
  グレーは既に `pending`(未入力)の意味を持っており、1色に2つの意味を持たせると線引きが壊れる
- **同じCSSプロパティを指定するクラスを重ねない。**Tailwind は class 属性の順ではなく
  出力されたCSSの順で勝敗が決まるため、`border-transparent` と `border-primary/45` を
  同時に持たせると枠線が消える(実際に踏んだ)
